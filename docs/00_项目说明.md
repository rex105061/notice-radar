## 一、项目定位

14 天作品集项目，目标是产出一个**公开可访问、可演示、可评测**的 AI 应用作品，
补齐"产品文档 + 评测体系 + AI 应用落地"三处能力缺口。

- 起止：2026-10-16 → 2026-10-30
- 时间预算：工作日 90 min/天 + 周末 4 h/天，合计约 23 小时
- 主源文档：`../../2周每日执行表_公告雷达_20261016修订版.md`

## 二、合规红线（不可逾越）

1. **数据只用公开信息**：交易所 / 巨潮资讯网公开公告。绝不用雇主或客户的内部材料、未披露信息。
2. **定位"AI 辅助解读"，非投资建议**：所有输出显著标注「内容由 AI 生成，仅供参考，不构成投资建议，使用前须人工复核」。
3. **脱敏**：不出现任何客户公司名称、雇主内部流程细节。
4. **不爬需登录/付费的数据源**，不使用违反网站规则的抓取方式。
5. **评测集"正确答案"人工标注并留痕**。

## 三、技术选型与理由

| 选择 | 理由 |
|---|---|
| 数据源：巨潮资讯网 | 法定披露平台，公开免费、无需登录；合规叙事最干净 |
| 存储：SQLite | 单文件、零部署、够用；2000 条量级不需要数据库服务 |
| 正文：PDF + PyMuPDF | 公告正文本体就是 PDF；PyMuPDF 纯 Python、无外部依赖 |
| LLM：DeepSeek | 中文金融文本表现好、成本低、OpenAI 兼容协议（换模型只改 3 行） |
| 前端：Streamlit | 一天能出可演示页面；不追求美观，追求"点得开、看得懂" |

## 四、目录约定

```
src/     核心代码（config / fetch / extract / interpret / cli）
docs/    文档（项目说明 / PRD / 评测规范）
eval/    评测集与标注表
data/    本地数据，不入库（notices.db、pdf 缓存）
```

## 五、人机分工（本项目的执行原则）

- **业务判断由作者本人完成**：产品定义三句话、抽取 schema、评测集人工标注、badcase 归因、PRD 业务流程。
- **工程实现可借助 AI**：抓取、建表、页面、评测脚本、部署、调试。
- **一条判据**：如果面试官问"你为什么这么设计"，答得上 → 可以交给 AI 做；答不上 → 自己做，或让 AI 做完后讲透。
- **一条红线**：最危险的失败不是"做不出来"，而是"做出来了但说不清它怎么工作"。
