# 公开介绍帖 · 三个版本

> 用途：发在 LinkedIn / 即刻 / 小红书 / 朋友圈，或作为简历里的项目描述。  
> 原则：给事实和数字，不写"我学到了很多"这类总结句。

---

## 版本 A：主版本（约 220 字，适合 LinkedIn / 即刻长文）

我做了一个「公告雷达」。

起因很具体：做 IR 的时候，公告一挂网，机构的微信就开始进来问"这条怎么看"。要判断这条意味着什么、对方会追问什么、口径怎么给才不越界——这三件事每次都要从头想一遍。

现成的工具（巨潮、东财、Wind）解决的是「公告说了什么」，不解决「这条对我意味着什么」。所以我做了一个最小版本：输入股票代码，把每条公告变成一句话判断、买方和卖方各自的追问清单、一份可以直接用的口径草稿，并标出口径里哪句话有合规风险。

现在库里是 37,508 条 A 股公告（10/15–11/12）。在 8 条人工标注的真实公告上：解读准确率 90%，口径可用率 87.5%，合规漏报 0 条。

还没解决的是：内置的质量分和人工判断不相关——它衡量的是"公告信息有多丰富"，不是"解读有多好"。这条我写进了 badcase 档案，正在重做。

在线试用：<https://notice-radar-jzfkesvjwzcbhabnuw79pt.streamlit.app/> （免费实例会休眠，首次打开可能要等 10–20 秒）  
代码：<https://github.com/rex105061/notice-radar>

## 版本 C：技术版（适合发给工程背景的人 / 技术社区）

**公告雷达** —— A 股公告的 LLM 结构化解读与合规口径生成

- **数据**：巨潮资讯网公开接口，按天抓取（跨天查询会被静默截断，这是踩过的坑），37,508 条 + PDF 正文解析（PyMuPDF）
- **模型链**：抽取（temperature 0.1）→ 解读（0.3）分两次调用，避免抽取阶段开始"脑补"
- **合规判定**：6 条词面红线由人定死，模型只做命中判定，不自己发明标准
- **评分**：规则计算而非 LLM 自评，四项可解释（事实落地 / 数字一致 / 合规安全 / 输出完整）——但已发现该指标测的是信息丰度而非质量，正在重做
- **评测**：8 条人工标注，解读准确率 75%、口径可用率 87.5%、合规漏报 0
- **工程**：Streamlit + SQLite + GitHub Actions 每日自动更新 + 按需抓取正文（演示版每会话限 3 条，防额度滥用）

仓库：<https://github.com/rex105061/notice-radar>
